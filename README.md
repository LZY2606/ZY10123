# LiDAR 航带特征点刚体平差试验台

这个项目面向已抽稀的 LiDAR 特征点、控制点和重叠航带候选对应。它不读取 LAS/LAZ，也不渲染海量点云；坐标、坐标系标识和长度单位按导入请求原样保存。系统包含 FastAPI 后端、无外部矩阵库的确定性数值核心、SQLite 存储和一个无 CDN 依赖的浏览器页面。

## 安装与演示

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pytest -q
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 5323
```

打开：

```text
http://127.0.0.1:5323
```

首次启动默认创建一个小型确定性演示数据集。设置 `SEED_DEMO=0` 可关闭演示数据。SQLite 默认路径为 `data/app.db`，可用 `LIDAR_DB_PATH=/path/to/app.db` 覆盖。

## 坐标方向与组合规则

所有校正变换只使用一个明确方向：

```text
common = R * (local + a * u) + t
```

- `local`：航带采集文件中的局部特征点坐标。
- `common`：控制点所在公共坐标系下的坐标。
- `R`：旋转矩阵，由微小旋转向量 `(omega_x, omega_y, omega_z)` 经 Rodrigues 公式生成。
- `t`：校正段平移。
- `a * u`：仅 `drift_v1` 使用的局部坐标帧线性缓变漂移；`u` 是点在所属校正段内的归一化时间，范围 `[0, 1]`，先作用于局部点再旋转。
- 迭代更新固定为左复合：`R_new = exp(delta_omega) * R_old`。
- 反向变换使用 `R^T`，且先减公共平移，不允许把矩阵左右乘混用。

反算公式是：

```text
local = R^T * (common - t) - a * u
```

## 坐标系和单位

导入时必须提供：

- 数据集级 `common_crs` 与 `common_length_unit`。
- 每条航带的 `local_crs`、`time_unit`、`time_epoch` 和 `local_length_unit`。
- 源元数据可放在 `metadata` 中，系统不解释、不重投影、不转换。

导入会原样保存每条航带的本地长度单位，单位不同也不会覆盖或静默换算。支持的长度单位标记为 `m`、`ft`、`survey_ft`。为避免把英尺和米的数值直接放入同一最小二乘模型，求解混合单位数据集时会明确拒绝；需要换算时必须在系统外形成带清晰来源和单位声明的新输入。系统不补造源坐标、CRS 或单位。

## 模型版本

- `rigid_v1`：一组公共旋转和公共平移；忽略航带分段，请求中传分段会返回 422。
- `strip_offset_v1`：公共旋转，每条航带或每个校正段有独立平移。
- `drift_v1`：公共旋转，每条航带或每个校正段有独立平移与线性时间漂移。

分段时间必须严格位于航带 `time_start` 与 `time_end` 内部。分段采用左闭右开规则：

```text
[start, split) + [split, end]
```

时间刚好等于 `split` 的点只属于后一段，不会同时进入两段，也不会被重复计数。

## 残差口径

所有残差与阈值都在公共坐标的长度单位中，默认演示数据单位为米。

- 控制点残差：`common_measured - common_predicted`。
- 重叠对应残差：`right_common_predicted - left_common_predicted`。
- 残差表展示三维向量和欧氏范数。
- 权重按最小二乘乘子 `sqrt(weight)` 进入观测行。
- 锁定控制点使用严格等式约束，不通过极大权重近似。
- 禁用项不参与求解，但保留在方案诊断中；超限项标记为 `rejected`，作为拒识证据保存，不会被删除。

设置 `residual_limit_m` 后，先完成一次完整平差，再把接受集中范数超过阈值的对应标记为拒识并重新求解。拒识后若剩余观测不足以约束某条航带或校正段，求解状态为 `degenerate`，不会保存一个“看起来成功”的方案。

## 秩亏损与多候选

求解使用列选主 Householder QR 和确定性 Gauss–Newton 迭代；没有随机初始化、岭回归、阻尼或隐式正则化。

若秩小于自由度数，返回：

- `rank`
- `degrees_of_freedom`
- `unconstrained_directions`
- 多个可行参数候选 `candidates`
- 控制点几何秩与退化警告

`free_parameters_zero` 只是把未约束自由参数置零的特定解，不表示唯一答案。其他候选沿规范化空方向分别移动一个无量纲单位步，供用户判断不可识别方向。

## 不可变性与派生

- `points` 表保存原始局部点坐标，求解和发布不会更新这些坐标。
- 修改禁用集、锁定点、权重、拒识阈值、模型或分段时，都创建新的方案 ID。
- 方案 ID 来自规则指纹；数据集 ID 来自完整输入指纹。
- 已发布方案不覆盖、不删除；发布动作只把该方案的状态改为 `published`。
- 每个方案保存接受、锁定和拒识的控制/对应证据、权重、残差、模型版本和规则指纹。

## 作业、指纹与恢复

每个请求都必须带客户端提供的 `job_id`：

- 完整请求体生成输入指纹。
- 数据集输入、模型版本、配置、父方案和求解器版本生成规则指纹。
- 同一个 `job_id` 重放同一请求会返回原作业，不重复写入审计事件。
- 不同请求复用同一 `job_id` 返回 409。

数据集、点、方案、证据、作业和审计事件在 SQLite 立即事务中提交。若进程在提交前退出，事务回滚，不会留下部分改变的点集；重启后可：

1. 打开页面或访问 `/api/health`，系统自动执行幂等建表。
2. 用原 `job_id` 和原请求体重放作业。
3. 通过 `/api/jobs/{job_id}` 查看作业状态、指纹和审计事件。
4. 若数据库文件损坏，先保留 `data/app.db` 作证据，再设置新的 `LIDAR_DB_PATH` 重新导入原始特征点集。

## 主要 HTTP 接口

- `GET /api/health`：健康检查。
- `GET /api/datasets`：列出数据集。
- `POST /api/datasets/import`：导入航带、点、控制和对应。
- `GET /api/datasets/{dataset_id}`：查看保真的源数据。
- `POST /api/schemes/solve`：派生新方案；秩亏损时返回失败作业和候选。
- `POST /api/schemes/publish`：发布已创建的方案。
- `GET /api/schemes/{scheme_id}`：方案、证据和变换点。
- `GET /api/compare/{left_id}/{right_id}`：同数据集两个方案并排比较。
- `GET /api/jobs/{job_id}`：作业与审计事件。

## 页面功能

- 切换三种模型版本。
- 禁用一组对应或对应组。
- 禁用或锁定控制点。
- 修改单个控制或对应权重。
- 为 `strip_offset_v1` 或 `drift_v1` 设置每航带二分时间。
- 平面图、x-z 高程剖面和残差分布图查看局部折断。
- 两个方案并排比较秩、变换方向、拒识项、残差证据和图形。
- 秩亏损时显示空方向与候选参数，不提供静默“修复”按钮。

## 测试

测试覆盖：

- 坐标方向和严格往返。
- 矩阵左复合与小角度旋转恢复。
- 分段端点唯一归属。
- 刚体、分段平移和缓变漂移。
- 控制点等式锁定。
- 自由度不足、控制点几何退化和空方向。
- 超限对应拒识但保留证据。
- 原始点不被改写。
- 方案并排比较。
- 作业重放和审计事件幂等。
- 异常输入不产生部分点集。

```bash
.venv/bin/pytest -q
```
