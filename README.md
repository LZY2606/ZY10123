# LiDAR 航带对齐试验台

在普通笔记本上试验 **刚体 / 每航带偏移 / 分段缓变漂移** 三种航带平差模型，
对比不同约束组合。不渲染海量点、不读取 LAS/LAZ；只处理已简化的特征点集，
但**点集、坐标系与单位的来源信息保真**。

## 安装与演示

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pytest -q
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 5323
```

浏览器打开 <http://127.0.0.1:5323>，点击右上角 **“载入演示数据”**。
交互式 API 文档在 <http://127.0.0.1:5323/docs>。

数据库默认是当前目录的 `lidar_align.db`（SQLite/WAL），可用环境变量
`LIDAR_ALIGN_DB=/path/to.db` 覆盖。

## 坐标方向（重要）

所有变换使用**明确的、按执行顺序书写**的方向约定，避免矩阵左乘/右乘混用：

```
p_target = R · p_source + t          # T: source -> target
(T_ab.then(T_bc)).apply(p_a)         # 先执行 a->b，再执行 b->c
T.inverse()                           # 精确逆（正交旋转），不是“差不多”的近似逆
```

* 本项目中方向恒为 **局部航带坐标系（source）→ 公共控制坐标系（target）**。
* 求解器对刚体使用**局部 SE(3) 扭量增量**（`T ← T ∘ Exp(δ)`，Rodrigues 参数），
  旋转始终精确停留在流形上；大角度修正不会因“往返差不多”累积误差。
* 平移以 **米** 存储，旋转以 **弧度** 存储；Rodrigues 参数 = 旋转轴 × 角度。

## 单位与数据保真

导入时（`POST /api/pointsets`）：

* 原始局部坐标 `x/y/z` 与来源单位 `unit`（`m`/`cm`/`mm`/`ft`/`us_survey_ft`）、
  来源 CRS `crs`、来源说明 `source_description` **原样存库**，绝不就地改写。
* 求解/视图统一在米下进行，缩放因子 `unit_scale_to_m` 随点集持久化；
  未知单位直接报错（不猜）。
* GCP 控制坐标带独立 `control_unit`/`control_crs`；本工具只做单位归一，
  **不做任何跨基准/坐标参考系变换**——CRS 不同需要先在外部完成。
* 归一化沿航带位置 `s ∈ [0,1]`：优先用采集时间线性归一；缺时间时用
  水平路径长度累积归一。该量用于缓变漂移模型，可由 `/data` 端点复核。

## 模型版本

模型布局冻结，发布后改动会升版本号：

| 版本 | 参数 |
|---|---|
| `rigid6-v1` | 一个全局 6 自由度刚体变换（平移 3 + Rodrigues 旋转 3） |
| `strip_offset3-v1` | 每条航带一个 3 分量平移（tx, ty, tz） |
| `strip_drift-v1` | 每航带沿 `s` 的分段线性平移（每节点 d 是 3 分量）+ 一个共享全局小旋转 |

### 分段与端点归属（单段归属）

漂移节点为 `b0=0 < b1 < … < bn=1`，区间 `[b_k, b_{k+1})` 内

```
corr(s) = (1-u)·d_k + u·d_{k+1},  u = (s - b_k)/(b_{k+1}-b_k)
```

**恰好在内部节点 `s == b_k` 上的点只属于前一段（较早的一段）**，取恰好
`d_k`（`u=1`），不会被两段重复混合，也不同时属于后一段。分段在 UI 中
对某条航带输入内部断点（如 `0.33, 0.66`）派生为新方案。

漂移模型存在一个真实的**规范自由度**（所有节点加常数、全局平移减同一常数，
点不变）。它通过一个**显式、权重可见的基准锚固观测**（每条航带首节点
`w_gauge·d_0 = 0`，默认 `drift_gauge=100`）消除；平滑变化则是普通加权观测
`w_smooth·(d_{k+1}-d_k)`（默认 `smooth=1`）。两者都不是隐藏的 Tikhonov
正则化，权重在方案配置中可见可改。

## 残差口径

* **GCP 残差**（米）：`r = corrected(local_point) - control_xyz`，3 分量 + 范数。
* **航带对应残差**（米）：`r = corrected(p_a) - corrected(p_b)`。
* 行权重：GCP 默认 `w=10`；对应 `w=1`；锁定 GCP 额外乘 `lock_factor=1e4`。
* 报告的 `rms_m` 是**全部活动观测**（未加权的）3 分量残差 RMS；表格逐行
  给出分量与范数。被拒对应也参与证据日志的残差展示，但不参与求解。
* **离群剔除**（确定性）：每次只剔除范数最大且超过 `outlier_sigma`
  （默认 0.5 m）的单个对应，然后从零重建重新求解，直到无超限。
  被拒对应保留在结果中并标记 `accepted=false` 与拒绝原因，**绝不删除**。

## 自由度不足 / 几何退化

法方程用 SVD 求逆。当秩不足时求解**不会**用正则化偷偷选一个解，而是返回：

* `status="rank_deficient"`、`rank / n_params`、奇异值；
* **未受约束方向**（零空间向量 + 参数标签，如 `global.rx`）；
* **多个同样可行的候选**：最小范数特解，以及沿每个零方向 ±1 步长的候选，
  并附其加权残差范数。前端以红色错误框 + 黄色候选框展示。

仅靠共线/共面 GCP 无法约束某些旋转或平移时即可复现（例如禁用 GCP 使只剩
共线两点）。测试 `tests/test_solver_degeneracy.py` 覆盖方向、端点与这些错误。

## 不可变性、方案派生与比较

* 原始点只写一次；方案（plan）只追加：任何禁用一组对应、锁定 GCP、分段、
  改阈值的操作都通过 `POST /api/plans/{id}/fork` **派生新方案**
  （记录 `parent_plan_id`）。已发布方案不可再改，系统也没有 PUT/PATCH 入口。
* 每个方案保存**所用控制点、被接受的条带对应（含被拒证据）、权重与模型版本**。
* 两个方案可并排比较（`GET /api/plans/{a}/compare/{b}`），前端同时画
  校正后平面图与高程剖面。
* 页面三视图：**平面图（x-y）**、**沿航带高程剖面（s-z）**、**残差分布直方图
  （含 σ 阈值线）**，用于定位局部折断。

## 作业、指纹与审计

* 作业指纹 = SHA-256(输入数据摘要 + 方案配置 + 规则版本 `rules-2026-09-20-v1`)，
  规范化 JSON（键排序、无空格、`allow_nan=false`）。
* **重放同一作业返回已存作业行，不重复产生审计事件**
  （`audit_events.event_key` 有 UNIQUE 约束）。
* 作业状态机 `queued → running → succeeded/failed` 只允许合法迁移。
  `queued`（含审计）先落盘，再 `running`，求解本身不写点数据，最后落结果。
* **异常退出不显示部分已改变的点集**：点不可变且求解不改点；进程在
  queued/running 中死亡后，启动时把残留作业恢复为 `failed`
  （错误信息带 `[recovered: ...]`）。导入在单事务中完成，中途崩溃整批回滚，
  不留半个点集。可用 `simulate_crash: true` 对导入/作业注入故障演练。

## 恢复步骤

1. 重新启动服务：`.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 5323`
   （启动自动恢复残留 running/queued 作业为 failed）。
2. 打开“审计日志”查看 `job_failed` / 恢复记录与对应作业、方案。
3. 原始点集与历史方案都还在；**不要**就地改方案，而是从该方案
   **fork** 一个新方案（禁用问题对应 / 锁定 GCP / 分段 / 调阈值）后重新求解。
4. 若数据库文件损坏，删除该 `.db`（含 `-wal`/`-shm`）后重新导入；
   导入载荷可通过 `GET /api/demo` 获取演示样本，真实载荷由调用方保存。
